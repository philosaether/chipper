2026-04-23: Chipper repo initialized. Architecture accepted (designs/chipper-architecture.md). Standalone React library: sentence > clause > chip hierarchy, six domain archetypes, tree-scoped context, palette with defaults + presets, builder API with clause composition, four chip modes, BEM + CSS custom properties, AA accessibility.
2026-04-23: Single repo for code + .meta/ (not the two-repo model). Design docs are shared artifacts that code traces back to.
2026-04-23: Tooling: Vite library mode, TypeScript strict, Vitest, ESLint + Prettier. React 18/19 peer dep. BEM class prefix: chipper-.
2026-04-27: Domain factory pattern accepted (designs/domain-factories.md). Internal createDomain<T> base, archetype factories as public API. All configs accept optional consumes/produces/onContextChange pass-throughs. defaultValue and placeholder are separate concerns: defaultValue is initial T, placeholder is display text for invalid state. Enum defaults to '' (invalid), not keywords[0]. No Object.freeze — immutable by convention.
2026-04-27: State reducer pattern accepted (designs/state-reducer.md). SentenceStore = { state, domains }. Domains resolved once at init, keyed by chipId. displayValue computed in reducer (not component). One file per action handler from the start. SET_CHIP_VALUE implemented for vertical slice; TOGGLE_CLAUSE, SET_CONTEXT, SET_LIVE_VALUE typed but stubbed.
2026-04-28: React hooks design accepted (designs/react-hooks.md). Single SentenceContext carries store + dispatch + definition + popup state. useSentence (sentence-level access), useChip (chip state + setValue), usePopup (singleton open/close). Popup is UI state (useState), not reducer state. useClause deferred until TOGGLE_CLAUSE. SentenceProvider wraps useReducer + onChange. Definition static per mount.
2026-04-28: Interactive components design accepted (designs/interactive-components.md). Chipper wraps SentenceProvider + Sentence. Thin components — hooks own state, CSS owns appearance. Per-domain color via inline CSS variable (--chip-trigger-color), not BEM modifier per color. EnumPopup owns close-after-selection. Outside-click via mousedown + setTimeout(0). Popup unmounts when closed.
2026-04-28: Demo page v0.1 accepted (designs/demo-page.md). Single vertical-slice sentence, live state inspector, explainer text. Demo-specific --chip-color-month token in demo.css (not library defaults). Page structure is foundation for future complexity-tiered showcase.
2026-04-28: ClauseDefinition now uses segments model (interleaved TextSegment + ChipSegment). Builder .lead() replaced by .text(). chips[] kept as derived convenience for initializer/reducer. Resolved the "Every [2] [weeks] on [Monday]" problem from the architecture doc.
2026-04-28: Vertical slice complete and merged to main. All five stages shipped: enumDomain, state reducer, React hooks, interactive components, demo page. 66 tests passing.
2026-05-12: Theming engine design accepted (designs/theming-engine.md). SASS architecture with token contract, praxis-theme as default. Separate sass CLI build (not Vite) for CSS. Pre-computed derived colors for legacy browser support. Token prefix --chipper- (breaking from --chip-). Ship base + theme split from day one. Pastel fills for valued chips, dashed borders for placeholders.
2026-05-12: Border affords mutability — interactive chips show domain-colored border at rest, readonly chips get transparent border. Visual distinction between editable and display-only.
2026-05-12: Chip color scheme matches Praxis: dark-on-pastel at rest, inverted pastel-on-dark for selected popup option. Expanded chip keeps normal colors with accent glow. Popup pills use domain colors throughout.
2026-05-12: keywordOrExpressionDomain design accepted (designs/keyword-or-expression-domain.md). Domain<string>, keywords-first popup layout (input below), two-level validation (keyword match OR expression validate). expressionDomain shipped as convenience alias (empty keywords). No separate expression-only archetype.
2026-05-13: multiSelectDomain + alternativeCoordinateDomain design accepted (designs/multi-select-alt-coordinate.md). multiSelect: Domain<string[]>, toggle grid popup, group keywords as shortcuts, 3-then-count display. altCoordinate: Domain<string>, tabbed popup with slots model for multi-DOF modes (compose/decompose). allowCreate deferred — entangled with backend persistence.
2026-05-13: Domain<T> gets optional `meta` field (Record<string, unknown>) for archetype-specific data passed through to popup rendering. Cleaner than casting or extending the interface per archetype.
2026-05-13: Multi-select display uses implicit keyword matching — if the current selection matches any group keyword's value set (regardless of how the user arrived there), display the keyword label. No path-tracking state needed.
2026-05-13: Numeric expression mode via `inputType: 'number'` on ExpressionConfig. Adds min/max/step fields. NumericInput component renders stepper UI (− value +). Value remains string throughout — stepper operates on numbers internally.
2026-05-13: Stepper expression mode scoped to integers. Continuous/float values should use a future `inputType: 'slider'` expression mode instead of adding float precision hacks to the stepper.
2026-05-13: Visual polish design accepted (designs/visual-polish.md). Popup flex-wrap for all types, --chipper-popup-font-size token (0.875rem), --chipper-popup-max-width (20rem), pill min-height 1.5rem (WCAG AA), CSS popup caret, contrast fixes for copper/teal/umber/text-muted, multi-font demo page (6 panels). Multi-line sentence layout deferred to TOGGLE_CLAUSE.
2026-05-14: Reference domain design accepted (designs/reference-domain.md). Domain<string>, ReferenceSource with getItems(path)/search/resolveDisplay, ReferenceItem with id/label/hasChildren/selectable. Mutable display cache on domain instance. Trust-all validation. Tags/allowCreate deferred as multi-select enhancement, not reference variant.
2026-05-14: Composite domain is a coordination pattern (approach B), not a new archetype. Enum/KOE parent chip + contingent clause of child chips. Needs TOGGLE_CLAUSE + SET_CONTEXT engine work first. Deferred until after reference domain.
2026-05-14: Indigo (#3d4a8c / #dfe3f5) added to praxis color palette as 10th hue role for reference domains. WCAG AA: 5.68:1 on pastel, 7.19:1 on white. Added to color-scheme.md for cross-project availability.
2026-05-14: Contingency engine design accepted (designs/contingency-engine.md). Clause presence (engine-controlled) and activation (user-controlled) as separate ClauseState fields. Tree-scoped context propagation. Domain reconfiguration via configure() + onContextChange(). Recursive cascade through contingency forest. Definition reference on SentenceStore. Composite domain is a coordination pattern using these primitives, not a separate archetype.
2026-05-16: LineDefinition introduced as intermediate DOM layer between sentence and clause. Lines group one or more clauses into a visual row; sentence stacks lines vertically. Builder gets .line(options?) to start a new line. Backwards compatible: sentences without explicit lines render each clause on its own line.
2026-05-16: Builder DX design accepted (designs/builder-dx.md). Rename clause()→builder(), chip ID implies domain name, produces() string shorthand, Keyword.displayLabel, defaultValue→default with first-keyword fallback, extendPalette({chips,patterns}) consumer-facing rename, expression helpers (textExpression/numericExpression) colocated with KOE domain, shared keyword normalization across all domains. No deprecated aliases — pre-v1, no users to migrate.
2026-05-16: Default value cascade: explicit default > placeholder triggers empty default > first keyword fallback. Placeholder means "user must choose" — chip shows placeholder text with dashed border. No placeholder + no default = first keyword is fine.
2026-05-16: Chip-level contingency design accepted (designs/chip-contingency.md). Segments (chips and text) get optional present predicate. visibleChips stored on ClauseState (undefined = all visible). Hidden chips excluded from context production. Text visibility evaluated at render time. All chips produce simultaneously (no left-to-right ordering). Solves the diamond dependency problem from the cadence pattern.
2026-05-20: Mode-switching design accepted (designs/mode-switching.md). ExpressionConfig gets optional trigger (label + default). Trigger keyword enters expression mode, regular keywords exit. expressionMode boolean on ChipState. Symbol sentinel in SET_CHIP_VALUE for atomic mode+value change. Three popup states: keywords-only (no expression), always-on (no trigger), trigger-gated (trigger present). Always-on expression chips unchanged.
2026-05-20: Typing a keyword value while in expression mode exits expression mode. The reducer can't distinguish "user clicked keyword pill" from "user typed the keyword string into expression input" — both dispatch the same value. Treating keyword-matching values as keyword selections is correct for the general case. Edge case where it's undesired (user wants to stay in expression mode with a keyword-colliding value) left unsupported.
2026-05-20: ExpressionConfig gets optional prefix/suffix strings (or context functions) rendered flanking the input in the popup. HR separator between keywords and expression when both visible. Expression display on chip trigger wraps value with resolved prefix/suffix.
2026-05-20: domain.display() and computeDisplayValue() accept optional SentenceContext. SET_CHIP_VALUE builds clause context before computing display. revalidateClauseChips recomputes display when context changes. Enables context-aware chip trigger text.
2026-05-20: Keyword.label accepts string | ((context) => string). All popup components resolve function labels at render time. Keywords with function labels are excluded from static displayByValue map; domain.display() resolves them dynamically with context. Chip trigger shows context-aware keyword text (e.g., "next quarter" updates when cadenceUnit changes).
2026-05-20: Chips read ancestor context structurally via the contingency forest — no explicit consumes config needed. A chip in a clause contingent on a producing clause sees all ancestor productions via buildClauseContext.
2026-05-21: inputType: 'date' added to ExpressionMode and ExpressionConfig. dateExpression() helper with YYYY-MM-DD validation. Native calendar picker in KOE popup, submits on change. General-purpose expression type for date-picking chips.
2026-05-21: contingentOn() overloaded — accepts bare function as shorthand for presence-only contingency. Object form still works for cases needing configure. No new builder method.
2026-05-21: Lines auto-indent when all their clauses are optional or contingent. Explicit indent on LineDefinition overrides. Derived in Sentence.tsx render, no engine changes.
2026-05-21: Dormant optional clauses render full segment text with chip display values inlined, muted italic styling, no chip borders. Chip state persists through deactivation — configured values survive toggle cycle.
2026-05-21: numericExpression default validate rejects empty string explicitly. Number('') === 0 was passing isNaN/isFinite checks, hiding placeholder text.
2026-05-21: alt-coordinate buildLabelByValue now respects Keyword.displayLabel, falling back to label. Previously always used label for chip trigger display text.
